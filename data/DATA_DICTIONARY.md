# Data Dictionary

Every file here was pulled from the [OpenF1 API](https://openf1.org/) - free,
no API key, no signup. This documents where each file came from, what every
column means, and the couple of things about the raw data that aren't
obvious until you've hit them.

**Race:** Belgian Grand Prix 2026, Spa-Francorchamps, 19 July 2026.
`session_key = 11334`. Generated by [`export_data.py`](../export_data.py) in
the parent folder - re-run that script and it rebuilds every file here from
scratch via the live API.

---

## session_info.csv

One row: which race this all is. From the `sessions` endpoint.

| Column | Meaning |
|---|---|
| `session_key` | The ID every other endpoint is filtered by |
| `meeting_key` | ID for the whole race weekend (this race + its practice/quali sessions) |
| `date_start` / `date_end` | Race start/end, UTC |
| `circuit_short_name`, `country_name`, `location` | Where |
| `session_type`, `session_name` | Both "Race" here - `session_name` is the one to filter on, since sprint races are `session_type="Race"` too |

## drivers.csv

Every driver entered in this race (22 rows). From the `drivers` endpoint.

| Column | Meaning |
|---|---|
| `driver_number` | The number used to filter every other endpoint |
| `name_acronym` | Three-letter code (NOR, VER, ...) |
| `full_name`, `team_name` | Self-explanatory |
| `team_colour` | Hex color, no `#` prefix - the app adds one |
| `headshot_url` | Official F1 driver photo |

## laps.csv

Lap-by-lap timing for the two compared drivers (NOR, VER), 44 laps each.
From the `laps` endpoint, with one extra column this project computed.

| Column | Meaning |
|---|---|
| `driver_code` | Added by this project - not in the raw API response |
| `lap_number` | 1-indexed |
| `lap_duration` | Seconds. Null for laps OpenF1 couldn't time (e.g. a red flag) |
| `date_start` | When the lap began, UTC - used to build the time window for pulling telemetry |
| `duration_sector_1/2/3` | Per-sector splits |
| `i1_speed`, `i2_speed`, `st_speed` | Speed trap readings (intermediate 1, intermediate 2, speed trap) |
| `is_pit_out_lap` | True on the lap right after leaving the pits - these run slower and get excluded from pace analysis |
| `clean` | **Added by this project.** True if this was a green-flag racing lap: not a pit out-lap, and lap time within 7% of that driver's own median. False laps are safety cars, red flags, or heavy traffic. |
| `segments_sector_1/2/3` | Mini-sector flags OpenF1 uses for track status coloring - not used in this project |

## stints.csv

Tire strategy: which compound each driver was on, and for how long. From the
`stints` endpoint.

| Column | Meaning |
|---|---|
| `stint_number` | 1st, 2nd, ... set of tires that race |
| `compound` | SOFT / MEDIUM / HARD (or INTERMEDIATE / WET) |
| `lap_start`, `lap_end` | Laps this set covered |
| `tyre_age_at_start` | Laps already on the tire when the stint began - nonzero if it's a used set (e.g. carried over from qualifying) |

## telemetry_full_race.csv

**The big one.** Every GPS position and speed sample for both drivers, every
lap of the race - 39,430 rows, ~4 samples/second per driver. This is the
row-level data the racing line, speed delta, and dominance-map plots are
built from.

It's a merge of two separate OpenF1 endpoints that don't share a key:

- **`location`** (`x`, `y`, `z`) - where the car physically was, sampled
  independently
- **`car_data`** (`speed`, `throttle`, `brake`, `n_gear`) - what the car was
  doing, sampled independently, on a slightly different clock

They're joined with `pandas.merge_asof` (nearest-timestamp match, 0.5s
tolerance) - see the main [README](../README.md) for why that's needed and
what can go wrong with a naive join.

| Column | Meaning |
|---|---|
| `driver_code` | NOR or VER |
| `lap_number` | Which lap this sample falls in |
| `date` | Timestamp, UTC, from the `location` side of the merge |
| `x`, `y`, `z` | Raw GPS position from OpenF1. **Units are decimetres (1/10 metre), not metres or feet - OpenF1 doesn't document this.** Measured by summing point-to-point distance around one lap and comparing to Spa's official length (7004m): 9.89 raw units per metre. |
| `x_m`, `y_m` | `x`/`y` converted to metres (÷10) - what the plots actually use |
| `speed` | km/h, from `car_data`, matched to this position by nearest timestamp |
| `throttle` | 0-100% |
| `brake` | 0 or 100 (on/off, not a real-valued pedal position in this API) |
| `n_gear` | Current gear, 0 = neutral |

Rows where no `car_data` sample fell within 0.5s of a `location` sample are
dropped rather than kept with a null speed - see `racing_line.py` for that
logic.

## Things about this data worth knowing before using it elsewhere

- **A query that matches nothing returns HTTP 404** with body
  `{"detail": "No results found."}`, not an empty list.
- **Timestamp formats are inconsistent between sessions** (some include
  microseconds, some don't), and occasionally within one response. Parse
  with `pd.to_datetime(..., format="ISO8601")`.
- **OpenF1 rate-limits fairly aggressively** for a free, keyless API. This
  export needed retry-with-backoff and per-lap throttling to complete
  without errors.
- **Not every session has full data.** Two 2026 races (Jeddah, Sakhir) had
  no lap data at all as of when this was built - OpenF1 hadn't backfilled
  them yet. Monaco 2026 has a ~50 minute gap in the middle of its telemetry.
- **Fuel load isn't in this data anywhere.** The tire degradation analysis
  needs it and has to estimate it - see the main README for how and why.
